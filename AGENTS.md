# PowerCanvas repository conventions

- For PowerCanvas product work, start with `.agents/skills/powercanvas/SKILL.md` and load only the relevant specialist references. Unrelated programming questions need no PowerCanvas workflow.
- Core schemas, compilers, registries, source hashes, ownership and plan/apply gates are authoritative. Agent recommendations and journals cannot override them.
- Use `node dist/cli/index.js version --json` and `capabilities --json` after building. Inspect command risk before execution; classify unknown commands before using them.
- Do not add unrequested tenant resources. Device adaptations normally remain inside one app. Preserve authorization scope; ordinary reads/planning do not need repeated permission.
- Keep generated runs in fresh `output/` directories and resumable fact journals under ignored `.powercanvas/agent/`. Never commit credentials, source exports or tenant evidence.
- `.agents/skills/` is authoritative. `plugins/powercanvas/skills/` is generated by `node scripts/package-agent-plugin.mjs`; do not edit those copies. Keep the legacy Taste entry point as a forwarding reference.
- Run `npm run check` and `npm run agent:eval` for agent changes; use appropriate existing browser checks for visual changes. Skill tests must not mutate a tenant.
- The V4.5 authoring evidence remains historical and unchanged. Do not retry that transport during skill/plugin development or promote maturity without accepted evidence.
