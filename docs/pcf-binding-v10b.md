## Field oracle and unexpected persistence

Microsoft Maker created **PowerCanvas PCF Field Binding Lab** on the existing Probe table. Maker based it on an existing form layout; that original form was not edited. The selected ExternalCode host was configured with ColorContrastField, bound `value`, and static text `theme=light`. No row value was entered. The captured final configuration UI showed Web checked, Mobile and Tablet unchecked.

The explicit **Save only** menu action issued one SystemForm POST. The recorded request contains no publication operation. The resulting form has `componentstate=0`; both RetrieveUnpublishedMultiple and the ordinary SystemForm query return the code-component configuration. The saved XML contains formFactor 1, 0 and 2 despite the final Web-only UI selection. The original creation payload itself contains all three, so this discrepancy predates readback parsing.

Therefore neither draft isolation nor UI-to-formFactor meaning is certified. The componentstate field is documented as internal-use metadata even though its labels identify 0 as Published; this report does not equate it with a runtime-access test. Further mutation was suspended pending the user's decision on this actual save behavior. No explicit form publish was performed, and no corrective mutation or deletion was attempted.

## What was learned

The observed field configuration establishes these facts for this oracle only:

- `controlDescription.forControl` matches exactly one base `control.uniqueid`.
- The base control's `id`/`datafieldname` identify the text column; its classid changes to a custom-control host class.
- `customControl.name` equals the observed installed component name, including prefix, namespace and constructor.
- The ID-bearing native fallback is retained separately. Its ID must not be mistaken for the installed PCF component GUID.
- `value` contains the logical column name with `type="SingleLine.Text"`.
- `theme` contains `light`, with `type="SingleLine.Text"` and `static="true"`.
- PCF entries contain no id or version attributes in this capture. No general version-serialization rule is inferred.
- The optional readOnly input was not configured. No output property exists in this manifest. Other property types remain unverified.

The saved component name is mapped to the installed record explicitly; package-folder inference is not used. Form-factor entries remain distinct opaque observations. The neutral parser remains unchanged and preserves unknown structures.
